# ADR-001: The clock is injected, never called directly

**Status:** Accepted
**Date:** 2026-08-16
**Decided by:** user (mandated by `docs/IMPLEMENTATION_PLAN.md` §3.1)

## Context

NirantharSeva escalates a referral when it has sat in a state longer than its
SLA window. Those windows are 24 to 120 hours. Experiments E1 and E2 sweep across
them, and E2 alone covers a grid of window sizes — running that against real wall
time takes weeks, inside a ten-week project.

Two further constraints make this non-obvious. First, the escalation sweep runs
in a **separate container** from the API, so any technique that manipulates time
inside the test process alone does not reach it. Second, invariant I7 requires
every experiment result to be reproducible from a seed and a config file; a
result that depends on when it was run is not reproducible.

## Decision

The system never calls `datetime.now()`. It asks a clock.

`app/clock.py` defines a `Clock` protocol with a single `now()` method.
`RealClock` returns `datetime.now(timezone.utc)`. `SimulatedClock` holds virtual
time and moves only when something calls `advance()`. The environment variable
`CLOCK_MODE=real|simulated` selects the implementation at startup, and
`SIM_START` seeds the simulated one.

The API receives the clock as a FastAPI dependency. The escalation scheduler
receives it as a constructor argument. Every timestamp the system writes —
`server_time`, `updated_at`, event times, SLA deadlines — comes from that one
source.

Because a single missed call fails silently, CI enforces the rule: a check that
greps the `server/app/` tree for `datetime.now(`, `datetime.utcnow(`, and
`time.time(` and fails the build. The lint rule is the enforcement; the
convention alone is not.

## Alternatives considered

| Option | Why not |
|---|---|
| `freezegun`, or monkeypatching `datetime` in tests only | Reaches test-process code only. The escalation sweep runs in its own container, so the experiment harness could not move its clock at all. Solves the unit-test problem and none of the experiment problem. |
| Use Postgres `now()` as the single time source | Moves the problem into the database, where it cannot be advanced without changing the container's clock. Also splits time between Python and SQL, so two parts of one transaction could disagree. |
| Compress the SLA windows for experiments — treat 24 hours as 24 seconds | Changes the thing being measured. Behaviour under a 24-second window is not evidence about a 24-hour window, and a panel would be right to say so. |
| Keep real time and run the experiment grid overnight | E2 sweeps windows up to 120 hours; the full grid is months of wall time, not a night. |

## Consequences

**Makes easy.** A 120-hour SLA experiment runs in milliseconds. Experiment runs
are deterministic and repeatable from a config file, which is what I7 requires.
Tests never need `sleep`, so the suite stays fast and non-flaky.

**Makes hard, and the honest cost.** Every module that needs the time must be
given the clock, which means slightly more wiring in constructors and
dependencies than calling a global would need. More seriously, **one forgotten
`datetime.now()` breaks experiment reproducibility without failing any test** —
the code works, the results are quietly wrong, and the symptom appears in week 9.
That is why the CI grep exists rather than a note in a style guide.

**A second cost, stated for honesty.** In simulated mode the timestamps the
system writes bear no relation to real wall time. Anything that compares a stored
timestamp to the host clock — a log correlation, a monitoring dashboard — is
meaningless in that mode. Nothing in the current design does this, and nothing
should start.

**How the benefit is measured.** Experiment E2 reports SLA-window results that
would have taken weeks of wall time; the runtime of that experiment is the
evidence that this decision paid for itself.

## Which invariant this protects

**I7** — every experiment result is reproducible from a seed and a config file.

Indirectly **I5**: escalation-correctness tests are only writable at all because
time can be advanced on demand.
